# ЭТАЛОН-main-workflow.json

Выгрузка боевого workflow «ИИ Тренер - Telegram Bot» (id `lX4BzBhka5FZp05G`) на 11.09.2026 (после программы тренировок и автопропуска напоминаний).
206 узлов, системный промпт 24 058 знаков, 21 инструмент-подворкфлоу. Эталон логики,
которую РФ-версия должна повторить на другом стеке.

## Токены вычищены — и почему они там были

В выгрузке нашлись **4 живых токена ботов Telegram**. Лежали они не в узлах, а в
`staticData.global.tokens` — это **намеренный кэш токенов**, сделанный ради отказоустойчивости:
чтобы бот продолжал отвечать, если Postgres, откуда токены читаются штатно, недоступен.
То есть это не забытый в поле секрет, а работающая часть конструкции.

Но следствие от этого не меняется: **любая выгрузка workflow несёт живые токены**.
Здесь они заменены на метки `<ТОКЕН-БОТА-N-УДАЛЁН>`; проверено повторным поиском — ноль
совпадений, структура, промпт и схемы инструментов не тронуты. Файл годен как справочник,
но не для импорта в n8n «как есть» (впрочем, `staticData` импорт всё равно не переносит).

Ссылки на учётные данные (`anthropicApi`, `httpHeaderAuth`, `postgres`, `telegramApi`)
остались — это только идентификаторы, сами значения хранятся в отдельной таблице
и в выгрузку не попадают. Здесь распространённое мнение верно; неверно оно только
про `staticData`.

## Правило

Выгрузка workflow перед попаданием в репозиторий проверяется на секреты — в первую очередь
`staticData`. Репозиторий уходит на GitHub, откуда секрет из истории уже не вычистить.

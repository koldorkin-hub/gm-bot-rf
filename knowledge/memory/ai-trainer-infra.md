**Две грабли, стоившие часа.** (1) **Сайт-прикрытие обязан согласовывать TLS 1.3 по X25519.** Сначала был выбран `www.rijksmuseum.nl` — он работает по P-256, поэтому Reality не мог довести чужое рукопожатие до конца: в логе сервера `target sent incorrect server hello`, у клиента «ошибка TLS-рукопожатия» и настоящий сертификат музея. Сбило то, что первая проверка случайно прошла (у сайта несколько узлов). Проверять ДО выбора: `openssl s_client -connect САЙТ:443 -servername САЙТ -tls1_3 -alpn h2 </dev/null | grep "Server Temp Key"` — нужен `X25519`, не `prime256v1`. Годятся tudelft, uva, leidenuniv, nu.nl, klm, asml, philips, utwente. (2) **Оператор владельца рвёт длинные TLS-сессии к этому адресу**: короткие фоновые запросы проходят, загрузка страницы обрывается с `read: connection reset by peer` со стороны телефона. Портом не лечится — лечится транспортом **XHTTP**: вместо одной длинной сессии много коротких веб-запросов.

Грабли диагностики: массовые `failed to read client hello` — это проверки доступности самим клиентом Happ, Reality на них намеренно не отвечает; судить по строкам `accepted tcp:`. И `pkill -f "xray run -config /tmp/…"` убивает сам ssh-сеанс, в командной строке которого встречается этот текст — убивать по сохранённому PID.

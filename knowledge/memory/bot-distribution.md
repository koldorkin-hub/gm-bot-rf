Раздача ботов фокус-группе (31.07.2026). **Ключевой факт, определивший схему: Telegram-ботов НЕЛЬЗЯ создавать программно** (@BotFather ручной, нет API, ~20/аккаунт). Поэтому «саппорт-бот сам заводит бота» невозможно; и нельзя одновременно иметь и полное самообслуживание, и личный бот каждому. Выбрана схема: **тир — per-bot (бот на группу), доступ — per-user.**

**4 бота (`clients`, каждый со своим токеном/webhook на `/trainer/<bot_id>`):** `gymak` (owner, @GymAK_AI_Bot), `trusted` (@TRD_Gymbot, `bot_type='trusted'` — фарма открыта, границы нет, [[research-pharma-boundary]]), `users` (@USER_GYMBOT, `bot_type='client'` — граница), `tclient` (тест, фейк-токен). Тир берётся из `clients.bot_type` (per-bot). ⚠️ Токены trusted/users живут в `clients.bot_token`; **trusted и owner БЕЗ границы → их ссылку давать только доверенным** (утечка = фарма-доступ).

**Доступ — per-user, таблица `user_access(bot_id, user_id, access_until date, note)`** (PK bot_id+user_id; `access_until` NULL=бессрочно, дата=free/оплачено до). **Гейт** в main ПОСЛЕ Access Gate (per-bot) и ПОСЛЕ проверки админ-команды: `User Access?` (EXISTS по bot_id+from.id и `access_until IS NULL OR >= current_date`) → `Пущен?` → внутрь / `Нет доступа` (сообщение с показом id пользователя, чтобы владелец мог выдать). Владелец засижен `INSERT user_access gymak/255171226 NULL` (иначе залочит себя — сеять ДО включения гейта).

**★ ОБНОВЛЕНИЕ 07.08.2026 (чат 6) — кнопочная BULK-выдача `/grant`.** `/grant` вынесен из `Админ?` в отдельный guided-флоу (для раздачи ~100 чел.). Кнопка `/grant` в меню owner-бота → тап → бот спрашивает формат + `grant_awaiting`; owner пишет ОДНИМ сообщением `<тир> <id id ...> <срок>` → подворкфлоу `AccessGrant01` парсит (тир user/client→бот `users`, trusted→`trusted`; НЕСКОЛЬКО id; срок ГГГГ-ММ-ДД|ДД.ММ.ГГГГ|Nd|free) → bulk upsert `user_access` (unnest) → подтверждение с ТИРОМ+@username+список+срок; не хватает — подсказка. Роутер в main как у рассылки (`Grant: чек`(PG grant_awaiting)→`как?`→`это выдача?`→вызов). Проверено вживую. `Nd` от UTC-now (иногда −1 день). Исходники `schema/build-accessgrant.js`, `transform-main-grant-menu.js`, таблица `grant_awaiting`. **`Админ?` теперь ловит только `/revoke //access //list`** (одиночные через `fn_admin_access`); `/grant` в старом формате `Админ?` больше НЕ обрабатывает — только новый guided.

**Админ-команды (старые, одиночные)** (в любом боте, только id владельца `255171226`, детект ДО агента через узел `Админ?`): `/revoke <bot> <id>`, `/access <bot> <id>`, `/list <bot>` (и БЫЛ `/grant <bot_id> <telegram_id> <free|30d|ГГГГ-ММ-ДД>` — заменён кнопочным guided, см. выше). Всё одной plpgsql-функцией `fn_admin_access(action,bot,uid,until)` → человекочитаемый ответ. `<bot_id>` — короткое имя (`users`/`trusted`), НЕ @username (частая путаница: `users`=@USER_GYMBOT, `trusted`=@TRD_Gymbot). `<telegram_id>` — числовой id, который человек видит в отказе «Твой ID: …».

**★ ОБНОВЛЕНИЕ 07.08.2026 (чат 6) — САМОЗАЯВКА + АВТО-ВЫДАЧА В ПЕРИОД.** Повод: презентацию раздают в сообщества, «вот твой ID» — тупик (владелец не даёт личный контакт незнакомым). Теперь отказ заменён на заявку: `Пущен?`[нет доступа] → `Заявка: обработать` (PG) регистрирует `access_request(bot_id,user_id,display_name,status,requested_at,digested_at)`; если бот **`bot_type='client'` И `current_date<=app_config.access_promo_until`** → **авто-выдаёт `user_access` до `access_grant_until`** (ON CONFLICT DO UPDATE, перекрывает истёкшие) → `Заявка: текст`→`Заявка: ответ`. Первое сообщение = заявка (без пересылки ID). **КРИТИЧНО: на trusted/owner авто-выдачи НЕТ** (только регистрация заявки) — иначе стороннему авто-открылась бы снятая фарма-граница; проверено (auto_granted=false на trusted). Окно/даты в таблице **`app_config`** (`access_promo_until`, `access_grant_until`) — меняются SQL без редеплоя. **ЛИМИТ (07.08.2026):** авто-выдача только если активных клиентов (`user_access` на client-ботах, непросроченные, без тест-диапазона) `< app_config.access_max_clients` (=80); сверх → `at_limit` → сообщение «бета-тест, число пользователей ограничено, заявка после 01.10.2026» (доступ НЕ выдаётся, заявка сохраняется для ручного /grant). `transform-main-access-limit.js`. Сводка новых заявок владельцу — `AccessDigest01` (cron 09:15 МСК, алерт-бот). Исходники `schema/transform-main-access-request.js`, `build-accessdigest.js`. Старый `Нет доступа` осиротел. Проверено вживую.

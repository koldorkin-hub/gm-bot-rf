Построено 11.09.2026 после жалобы владельца: бот назвал тренировку «отстающих» (День 4), а выдал упражнения понедельника.

**Причина путаницы (не модель, а данные):** описание тренировок жило сразу в трёх полях профиля — `active_plan`, `plan_week`, `goal_targets` — и они противоречили друг другу (старый сплит «верх–низ», промежуточный «Пн — Спина», новый 4-дневный); День 4 не был описан нигде. Плюс правило промпта «веди тренировку по прошлой, те же упражнения в том же порядке» превращало журнал в шаблон: после переделки плана бот копировал старую тренировку. Владелец: «почему он делает новую тренировку, а не заменяет старую?»

**Устройство.**
- Таблица `training_program` (bot_id, user_id, version, status active|retired, title, days jsonb, started_on, retired_on, note). Уникальный частичный индекс `training_program_one_active` — действующая ровно одна, это держит БАЗА, не промпт.
- Смена — только функция `set_training_program(bot, user, tz, title, days, note)`: FOR UPDATE действующей → retired → INSERT версии max+1, started_on = сегодня в поясе клиента. Функцией, а не изменяющими CTE: порядок изменяющих CTE в Postgres не определён (см. [[n8n-postgres-gotchas]]).
- Подчинённый workflow `ProgramTool01` (get / set). set проверяет days: массив, дни 1..N подряд без дыр, у каждого name и непустой exercises; в ответе агенту — дифф по дням и предупреждение, если дней стало меньше.
- Главный workflow: Load Profile дочитывает действующую программу, Build Profile Context печатает её строкой «ПРОГРАММА ТРЕНИРОВОК (действующая версия N…; единственный источник…)».
- Промпт: состав и порядок — только из программы; прошлый результат (веса/повторы) — через get_progress по тому же названию; разовая перестановка в зале программу НЕ меняет; постоянное изменение — get, затем set со ВСЕМИ днями. В `active_plan`/`plan_week` состав упражнений писать запрещено — там только календарь («Пн — День 1…») и уколы.

**Данные владельца:** v1 заведена от 18.08.2026 с названиями упражнений дословно как в журнале (иначе get_progress не находит прошлые веса). Пресс только в Днях 1 и 3 (решение владельца). Скрипты: `schema/program-reminder-migration.sql`, `schema/build-programtool.js`, `schema/transform-main-program-reminder.js`, `schema/program-reminder-data-20260911.sql`.

**Вторая итерация — в тот же вечер 11.09, после жалобы «ничего не исправилось, стало хуже».** Программа в базе была одна, но:
1. **Версию 1 я собрал из журнала, а журнал был грязным.** LogWorkoutTool с 31.07 переиспользовал ЛЮБУЮ сессию за дату, и кардио (эллипс, велотренажёр, шаги) дописывалось внутрь силовой. Эллипс попал первым упражнением Дня 4. **Урок: программу клиента берут из того, что клиент УТВЕРДИЛ в переписке (у владельца — сообщение 3427, «Остальное ок»), а не реконструируют из журнала.**
2. **Слои памяти вернули ошибку обратно.** «Нить диалога» (DialogSummary01) записала неправильную раскладку, которую бот сам выдал утром по старому правилу; «выжимка» (MemoryExtract001) с 20.08 хранила старый цикл. Модель смешала их с программой. Единственный источник истины не работает, пока сводки его дублируют.

Исправлено: кардио — отдельный список `training_program.cardio`, ProgramTool отклоняет кардио в силовом дне, у упражнения схема `{name, target}`; LogWorkoutTool кладёт кардио в отдельную кардио-сессию дня (решает код по названию, не только по kind; «Велосипед» с подходами — пресс, не кардио); история разделена только у `session_type='strength'` (12 сессий), `mixed` оставлены — там «ЛФК» и «шаги в полуприсяде» тоже помечены cardio; обе сводки получают флаг has_program и при нём не пересказывают состав дней; в профиле заголовки сводок при наличии программы помечены «состав дней мог устареть»; промпт — «ЧТО ГЛАВНЕЕ», «клиент говорит неверно → сначала get», «нет программы → зафиксировать согласованную с явным да». Скрипты: `program-cardio-migration.sql`, `workout-cardio-split-20260911.sql` (журнал отката `workout_cardio_split_log`), `transform-logworkout-cardio-split.js`, `transform-summaries-program.js`, `transform-main-program-cardio.js`, `build-programtool.js`, `owner-program-v2-20260911.sql`.

**How to apply:** если бот снова «путает дни» — сначала проверить, не просочился ли состав упражнений обратно в поля плана, и сколько версий в `training_program`, а не править промпт.

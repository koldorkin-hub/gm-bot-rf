Авария УСТРАНЕНА 18.07.2026, хвостов не осталось. Ценность записи — в порядке диагностики: если бот замолчал целиком, разбор начинать отсюда.

**Симптом:** запуски помечены `error` и падают за 40–1300 мс. **Причина:** узел `Postgres Chat Memory` бросал `no pg_hba.conf entry for host "91.228.153.233", user "n8n_user", database "n8n_memory", no encryption` — credential указывал на Postgres СТАРОГО сервера, чей `pg_hba.conf` нового IP не знал. Узел памяти общий для текстовой и голосовой веток, поэтому бот молчал везде сразу ([[n8n-bot-workflow]]).

**Что проверено и оказалось НЕ виновато** (сэкономит время в следующий раз): `N8N_ENCRYPTION_KEY` (был идентичен на обоих серверах), регистрация webhook в Telegram (`getWebhookInfo` чистый — 0 pending, без `last_error_message`), активность workflow, доступность внешних API.

**Правильное лечение** — не добавлять новый IP в `pg_hba` старого сервера (это законсервировало бы зависимость от выводимой машины), а перевести credential на локальный Postgres: host → `172.18.0.1`, шлюз docker-сети, уже разрешённый в `pg_hba` боевого сервера. Сделано: пароль роли синхронизирован, расхождение данных долито (72 строки, sequence выставлен), запуски 103 и 104 прошли `success`.

Грабля переноса scram-пароля между серверами, всплывшая в этой же починке, вынесена в [[n8n-postgres-gotchas]] п.3.

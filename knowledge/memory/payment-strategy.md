**Решение владельца (05.08.2026, чат 6). Оплата — самый последний этап, ПОСЛЕ теста фокус-группы. Ничего пока не реализуем.**

**Почему не Telegram-нативно:** Telegram обязывает цифровые товары/услуги ВНУТРИ Telegram продавать только за Stars (`XTR`); внешние платежи за цифру формально запрещены, наказание — Telegram скрывает бота от мобильных пользователей. Stars дорого для РФ (~30%: Apple/Google 30% при покупке звёзд на мобиле + Fragment ~2-3% на вывод в TON). У владельца Fragment есть и верифицирован (платил ТГ в TON за рекламу), но для РФ-клиентов дорого → Stars оставлены на «другой мир» (не-РФ) позже.

**★ ВЫБРАН Вариант 3** — внешний РФ-платёж вне Telegram: бот даёт ССЫЛКУ на платёжную страницу провайдера (с зашитым Telegram-id клиента) → клиент платит (СБП/карта) → провайдер шлёт **webhook** боту → n8n `UPDATE user_access.access_until` → бот подтверждает, доступ открыт. Гейт доступа и поле `access_until` УЖЕ построены (прошлые сессии). Внедрение ≈ один узел приёма webhook. Позиционировать как «доступ к сервису», НЕ рублёвый Telegram-инвойс за цифру и НЕ mini-app-магазин цифры с не-Stars (именно это Telegram детектит и наказывает) → риск бана низкий.

**Провайдер под автопродление — Prodamus** (для рекуррента лучший из рассмотренных): «клубная система»/рекуррент (период списания, демо, отписка, N попыток), 54-ФЗ (чеки в ФНС сами), 9 способов (карты, **СБП**, кошельки), webhook, работает без ИП/сайта (можно самозанятый). Цена: ~10 000 ₽ единоразово за форму + эквайринг 3,5%→2,7% с оборотом, 3 мес льгота 0% на первые 100к. Минусы: староватый интерфейс, нет моб.приложения, 10% на зарубеж. Альтернатива без разовой платы — ЮKassa (~2.8-3.5%), но рекуррент сложнее; с 2026 у ЮKassa НДС 22% на сумму комиссии.

**Вариант 4** (свой сайт + личный кабинет: оплата и управление подпиской на своём домене, бот — один из входов) — строить ПОЗЖЕ, ЕСЛИ фокус-группа даст хороший результат. Плюсы: свой бренд, единый аккаунт на все платформы, самый низкий риск бана; минус: много работы (сайт+аккаунты+привязка+ЛК) и лишние шаги для клиента (отвал на оплате выше).

**Пользовательский сценарий (Вариант 3), «бесплатный период кончился»:** уведомление в боте с inline-кнопкой «Оформить подписку» → тап → страница Prodamus (id зашит) → оплата СБП/карта (+согласие на автосписание) → webhook → `access_until=+30д` → «✅ подписка до DD.MM» → продолжает. Через 30д Prodamus списывает сам → webhook → продление без участия клиента. Списание не прошло → повторы → при провале бот пишет «обнови оплату: ссылка», доступ по дате. Отписка: `/unsubscribe`/ссылка → доступ до конца оплаченного периода.

**Порядок владельца перед оплатой:** дать доступ ~100 чел. на тест ≥1 месяц → аналитика ([[proactive-retention]] OwnerAnalytics01) + ошибки/пожелания из саппорт-бота ([[support-bot-system]]) → и ТОЛЬКО при подтверждённой активности вводить оплату. К внедрению: включить ТРИАЛ (на онбординге `access_until=сегодня+N дней` → тогда «период кончился» сработает по гейту), приём webhook Prodamus, определить тариф/период/длину триала. Раздача доступа сейчас — per-user `/grant` ([[bot-distribution]]); для 100 чел. может понадобиться массовая выдача. Связано: [[bot-distribution]] (user_access+гейт), [[n8n-multitenancy]].

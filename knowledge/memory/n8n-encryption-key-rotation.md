Выполнено 18.07.2026 на боевом сервере ([[ai-trainer-infra]]): старый ключ `AK1_n8n_secret_key_2026` был предсказуемым и лежал открытым текстом в compose, заменён на 64-символьный hex из `openssl rand -hex 32`. Перешифрованы все credentials того момента (telegramApi, anthropicApi, tavilyApi, postgres; tavilyApi позже удалён вместе с Tavily).

Порядок: выгрузить `n8n export:credentials --all --decrypted`, забэкапить базу и конфиги, остановить контейнер, сменить ключ, поднять, `n8n import:credentials` — импорт шифрует уже новым ключом, id сохраняются, workflow продолжает ссылаться на те же credentials.

Четыре грабли, каждая стоила отдельного круга:
1. **Ключ хранится в ДВУХ местах.** Кроме переменной окружения он лежит в `/home/node/.n8n/config` внутри тома, и при расхождении n8n не стартует вообще, уходя в цикл перезапуска с `Mismatching encryption keys`. Менять надо в обоих местах.
2. **`docker cp` кладёт файл владельцем root**, а n8n работает под пользователем `node` — импорт падает с `EACCES`. После копирования нужен `docker exec -u root <контейнер> chown node:node <файл>`.
3. **`import:credentials` возвращает «Successfully» даже когда залил НЕИЗМЕНЁННЫЕ данные.** 19.07.2026 на этом сгорела первая попытка ротации секретов: шаг правки JSON выполнялся в отдельном контейнере через bind-mount одного файла с тройным экранированием кавычек, молча не сработал, а импорт отчитался об успехе и вернул старые значения на место. При этом пароль Postgres сменился по-настоящему (прямой SQL без прослойки) — бот лёг с `password authentication failed`, а сгенерированный пароль исчез вместе с процессом скрипта. Выводы: правку делать `node`-скриптом ВНУТРИ контейнера n8n (файлом, не через `-e` с экранированием), а успех проверять сверкой отпечатков sha256 значений ДО и ПОСЛЕ, а не кодом возврата. Скрипты `/opt/rotate-secrets.sh`, `/opt/patch-creds.js`, `/opt/fix-pg.sh` на боевом сервере написаны так.
4. **`import:credentials` не обновляет `updatedAt`** — старые июньские таймстампы после успешного импорта это норма, а не признак того, что импорт не сработал. Проверять надо не таймстампы, а фактическую расшифровку: `n8n export:credentials --id=<id> --decrypted` и строку `Activated workflow` в логах.

Останавливать n8n на время таких работ через `docker kill`, не `docker stop` — [[n8n-bot-workflow]].

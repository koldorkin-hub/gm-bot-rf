```

  │              └─[ОШИБКА]────────────────┴──[ОШИБКА]──────────────────────┴──[ОШИБКА]──> Голос не распознан    │
  └─2 text ────────────────────────────────────────────────────────────────────────────────────────────────────┴─> AI Agent
                                                                                        AI Agent ──[успех]──> HTTP Request1 (ответ)
                                                                                                 └─[ОШИБКА]─> Извинение: ядро не ответило ─> Тревога: ядро (роняет выполнение)
```

**Ключевые решения, которые нельзя «упростить» обратно:**
- Гейт доступа считается в SQL (`access_ok`), а не выражением n8n — из-за неоднозначной сериализации `DATE`
- Запрос `Load Config` параметризован (`$1`), `bot_id` приходит из URL — иначе SQL-инъекция
- Межузловые ссылки только `.first()`, не `.item` — в голосовой ветке пары item рвутся
- Ключ памяти `{{bot_id}}:{{message.from.id}}` — именно `from.id`, не `chat.id`
- Повторов на `AI Agent` целиком НЕТ намеренно — переиграл бы весь цикл и оплатил токены дважды

## 10. Процедуры, которые нельзя пропускать

### Деплой изменений в workflow
```
1. export:workflow → точка отката в /root/…
2. правка JSON скриптом (писать файлом и scp — вложенные кавычки в ssh ломаются)
3. import:workflow
4. publish:workflow --id=…   (update:workflow устарела; без publish подчинённый
   workflow остаётся ЧЕРНОВИКОМ и вызов из родителя падает при active=1)
5. docker kill + docker start   (НЕ docker stop: SIGTERM обрывает идущие
   выполнения, а research идёт до 11 минут. Прежняя причина — deleteWebhook
   у telegramTrigger — больше не действует, этого узла в workflow нет)
6. СИНТЕТИЧЕСКИЙ ПРОГОН — обязателен: он прогревает кэш токенов,
   который обнуляется при каждом импорте
```

### Тест /research без сжигания денег
Глубина живёт в `research_config`. Для проверок логики (лимит, возврат, гейт)
временно уменьшить `max_sources`/`max_iterations`/`max_web_searches`, после —
вернуть 20/4/6. Логика лимита от глубины не зависит.
Боевые значения на 21.07.2026 сверены с БД: 20/4/6, синтез `claude-opus-4-8`,
помощник `claude-sonnet-4-6` — то есть после отладки всё возвращено на место.
Уронить PubMed для теста сбоя: `echo "127.0.0.1 eutils.ncbi.nlm.nih.gov" >> /etc/hosts`
внутри контейнера; вернуть — `grep -v eutils /etc/hosts > /tmp/h && cat /tmp/h > /etc/hosts`
(`sed -i` не сработает: файл бинд-монтирован).

### Безопасная проверка отказа Postgres
Строка `reject` в `/etc/postgresql/14/main/pg_hba.conf` **выше** разрешающих правил
+ `systemctl reload postgresql` + закрыть сессии `pg_terminate_backend`.
Сервер не останавливается, данные не трогаются. Откат — вернуть файл и перечитать конфиг.
Скрипт должен иметь `trap` на восстановление.

## 11. Грабли — где искать

Разложены по темам в памяти проекта (21.07.2026 разрезан разросшийся общий файл):

- `n8n-alerting-gotchas` — Error Workflow обязан быть активным; у узла Telegram нет режима
  «без разметки»; n8n обрезает текст ошибки по последнему «: »
- `n8n-deploy-gotchas` — импорт даёт ЧЕРНОВИК без `publish:workflow`; `staticData` не переживает
  импорт; `community-node --uninstall` не удаляет credential; `chown` каталога ДО экспорта;
  `sed -i` не работает по бинд-монтированному `/etc/hosts`
- `n8n-postgres-gotchas` — владелец таблиц должен быть `n8n_user`; `COPY TO` превращает переносы
  строк в `\n`; scram-пароль между серверами только через base64; безопасная имитация отказа базы
- `n8n-dataflow-gotchas` — `$input` после узла-параметров содержит НЕ входы вызова; HTTP-узел
  теряет бинарник; `require` в Code запрещён целиком; Gotenberg требует имя `index.html`
- `backup-restore-gotchas` — WAL в sqlite (нужен `VACUUM INTO`); `pipefail` ломает проверку gpg;
  entrypoint образа n8n подставляет `n8n`; BOM в PowerShell; права после `docker cp`
- `n8n-encryption-key-rotation` — ключ хранится в ДВУХ местах; `import:credentials` рапортует
  об успехе, залив неизменённые данные
- `n8n-dynamic-webhook-url` — путь с `:param` требует `webhookId` первым сегментом

**Общее правило, выведенное дорогой ценой:** проверять не код возврата, а фактический результат.
Успешный импорт ≠ изменённые данные. Настроенное уведомление ≠ доходящее уведомление.

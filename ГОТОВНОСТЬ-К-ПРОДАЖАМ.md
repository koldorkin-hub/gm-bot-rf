# Контрольный список: перед приходом первого клиента

Пока на сервере только владелец — ограничений нет, это решение принято сознательно.
Этот список закрывается **до того, как данные первого человека, кроме владельца, попадут
на РФ-сервер**. Участник фокус-группы считается таким человеком: его данные защищены
законом так же, как данные платящего клиента.

Ни один пункт нельзя пропустить «на пару дней» — именно так и возникают нарушения.

## Техника

- [ ] `REVOKE` прав роли `dev` на таблицы с персональными данными; проверить фактически
      запросом к `information_schema.table_privileges`, а не по коду возврата
- [ ] Урезать `sudo` пользователю разработки: без суперпользователя Postgres, без правки журналов
- [ ] Разработка переключена на базу с синтетикой по умолчанию
- [ ] `log_statement = 'all'` для роли `dev`, объём проверен
- [ ] Отгрузка журналов SSH и Postgres за пределы машины настроена и проверена восстановлением
- [ ] Обновить `CLAUDE.md`: снять пометку «этап 1», записать действующие ограничения
- [ ] Бэкапы РФ-сервера настроены и **проверены восстановлением**, а не только созданием

## Юридическое

- [ ] Поручение на обработку ПДн с площадкой подписано, спецкатегория «здоровье» допущена письменно
- [ ] Уведомление в РКН подано (или обновлено), сведения о поручении внесены
- [ ] Политика обработки персональных данных опубликована
- [ ] Форма согласия на обработку спецкатегорий: получение согласия встроено в онбординг бота
- [ ] Модель угроз и акт классификации ИСПДн оформлены
- [ ] Оферта и условия использования готовы, медицинских заявлений нет

## Продукт

- [ ] Прогон проверочного набора сценариев на РФ-модели пройден по порогам
      (см. `research/РФ-СТЕК-04-расчёты-eval-риски.md`)
- [ ] Предохранители безопасности проверены живьём: красные флаги, фарма, аллергены, РПП
- [ ] Тест на аккаунте владельца пройден полностью, найденные дефекты закрыты

Отметки о выполнении ставить с датой и ссылкой на коммит, где это сделано.

# РФ-стек «ИИ-Тренер»: на чём собирать, пока мало подписчиков (сводка от 06.09.2026)

Сводка четырёх исследований: модели (`РФ-СТЕК-01-модели.md`), размещение (`02-хостинг`), периферия (`03-периферия`), расчёты/eval/риски (`04-расчёты-eval-риски`). Цены — сентябрь 2026, курс ЦБ 86.6 ₽/$. Для сравнения: текущий счёт Claude за месяц — $407 ≈ 35 000 ₽ (до оптимизаций 04.09; новый уровень будет виден через неделю).

## Ответ на вопрос владельца

**Да, собрать РФ-копию без дорогих карт можно, и есть два честных пути.** Оба держат данные клиентов в России и оба дешевле нынешнего счёта Claude. Различаются они не деньгами, а тем, кто владеет железом и моделью.

| | Путь 1. Российское облако с открытой моделью (API) | Путь 2. Своя карта в аренде (RTX 5090 32 ГБ) |
|---|---|---|
| Стоимость LLM в месяц | **~3 000 ₽** (Cloud.ru: gpt-oss-120b или DeepSeek-V4-Flash) … 15–30 000 ₽ (Yandex AI Studio: Qwen3.6-35B) | **~46 000 ₽** (HOSTKEY, Москва); RTX 4090 24 ГБ — 27 000, но впритык |
| Модель | 120–300B (умнее любой 27B на одной карте) | Qwen3.8-27B int4 (лучший tool calling на одной карте) |
| Латентность хода | как у API, 3–8 с | 8–11 с на 5090; 14–18 с на 4090 |
| Данные | обрабатывает российский оператор по договору-поручению (152-ФЗ выполнен, как с любым РФ-облаком) | только наш сервер |
| Риски | провайдер снимает модели с 1–2-месячным сроком (Yandex: Qwen3-235B до 30.09, gpt-oss до 30.10.2026); лимиты RPM; нужно, чтобы оферта покрывала спецкатегорию (здоровье) | параллельность 3–5 на одной карте; всё обслуживание на нас; модель обновляем сами |
| Когда выгоден | сейчас и до ~1 000 пользователей (API ~25 000 ₽ при 1 000) | при желании полной независимости; экономически — от ~1 000 пользователей на дорогих моделях, от ~10 000 — безусловно |

**Рекомендация: начать с Пути 1, спроектировав всё так, чтобы Путь 2 включался сменой одной переменной (base URL и имя модели).** Своё железо не окупается никогда против API при нынешнем трафике: сборка на 5090 стоит ~650 000 ₽ и амортизируется 14–16 месяцев только против аренды карты, не против 3 000 ₽/мес.

Что общее для обоих путей и делается один раз: n8n + Postgres на российском VPS, распознавание голоса GigaAM-v3 на CPU, чтение документов Docling, поиск через Yandex Search API, eval из 90 сценариев как ворота качества.

## Главные факты из исследований

1. **Новинки из вашей ленты на одну карту не лезут.** GLM-5.3-Flash — 328 ГБ в FP8, DeepSeek-V4-Flash-Vision — 155 ГБ в 4 бита, Mistral Small 4 — 73–80 ГБ и без русского. Qwen3.8-Flash-Next: «6B активных» — про вычисления, на диске 180B, в 4 бита 96–114 ГБ, нужны 96+ ГБ RAM, один пользователь, лицензия не Apache. Зато **DeepSeek-V4-Flash и gpt-oss-120b доступны в российских облаках по API** — так большие модели становятся достижимы без своих карт.
2. **Для одной карты реальный шорт-лист из трёх:** Qwen3.8-27B (лучший tool calling: 90/90 одиночных, 28/30 многошаговых; vision встроен; дешёвый KV-кэш благодаря гибридной архитектуре), Gemma 4 31B (лучший русский — Arena RU 1468 против 1466 у Sonnet 4.6, но тяжёлый KV и открытый баг tool calling в vLLM), Qwen3.6-35B-A3B (самая быстрая, паритет с Claude по латентности, но «ум» уровня 9–14B и хрупкий int4). Российские открытые модели (T-pro 2.1, GigaChat Lightning, YandexGPT-5-Lite) уровня задачи не дают; T-pro интересен только измеренным русским tool calling при контексте 32k впритык к нашему входу.
3. **24 ГБ — впритык.** Qwen3.8-27B int4 + fp8-KV даёт 2–3 холодных / до 5 тёплых запросов по 32k и ход 12–18 с. **32 ГБ (RTX 5090) — лучшая точка цена/латентность**, 8–11 с. FP8 без вопросов к квантованию — только 48 ГБ (173 000+ ₽/мес в облаках — избыточно).
4. **int4 не убивает качество агента:** у Qwen3.8-27B Q4_K_M = BF16 на агентском Terminal-Bench (75 %) и на IFBench; обвал начинается на 2 битах. Уязвимое место — числа в аргументах инструментов (вес, даты, время) → кванты с эмбеддингами в 6–8 бит и обязательный eval. fp8-KV нейтрален, GDN-состояние не квантовать, q4-KV — нет.
5. **Ожидаемая просадка против Sonnet 4.6:** язык почти без потерь, предметная точность −15–20 %, следование длинному промпту 86–88 % против ~95 %. Значит детерминированные бэкстопы (справочник БЖУ, аллергены, валидация аргументов) из подстраховки становятся обязательными. Против Haiku 4.5 просадки не ожидается.
6. **Только CPU не годится для диалога:** prefill 25k токенов — минуты. Годится лишь для ночных сводок.
7. **Периферия решается дёшево и лучше нынешнего:** GigaAM-v3 (Сбер, MIT) — ошибок на русском втрое меньше Whisper, 0 ГБ VRAM, OpenAI-совместимый сервер `oaitt` (замена Groq сменой URL). Отдельная vision-модель не нужна — зрение встроено в Qwen3.8/Gemma 4. PDF — Docling + Tesseract rus (кириллицу включать руками), фолбэк — страница картинкой в модель. Поиск — Yandex Search API ~0.5 ₽/запрос.
8. **Юридика:** данные о здоровье — спецкатегория. При Пути 1 нужен договор-поручение с провайдером и подтверждение, что оферта допускает спецкатегорию (Cloud.ru рекомендует «внутренние» модели для 152-ФЗ, Yandex заявляет УЗ-1). Timeweb AI Gateway — шлюз к зарубежным моделям, не подходит. Зарубежный поиск только с текстом запроса без ПДн формально допустим, но требует скруббера — безопаснее Yandex.

## Что придётся переделать в боте (одинаково для обоих путей)

- **Агент:** под-узел Anthropic Chat Model → OpenAI Chat Model с Base URL; `stream: false`; Timeout 120 с; thinking выключен на сервере. Персону бота и профиль перенести после глобальных блоков и схем инструментов — иначе кэш префикса отдельный на каждый бот.
- **Инструменты:** первым узлом каждого tool-workflow — валидация аргументов по JSON-схеме с возвратом текста ошибки (модель починит вызов сама); правило «один инструмент за ответ, если результат нужен следующему»; `log_food` проверяет наличие результата `lookup_food`.
- **Ответ:** в узле нарезки — фильтр иероглифов (регенерация при CJK) и стриппер markdown; 3–4 критичных правила дублируются в штампе сообщения (вне кэша).
- **Голос:** Groq → `oaitt` (тот же multipart), конвертация OGG → WAV 16k float32 в контейнере ASR, без VAD/AGC.
- **Фото:** тот же OpenAI Chat Model; лимит 5 изображений на запрос; промпт «компоненты + размер порции», КБЖУ через `lookup_food`; визуальный safety-гейт перепроверить.
- **Документы:** нативный PDF-блок Claude → текстовый слой / Docling / страница картинкой в модель; фильтр инъекций детерминированно перед подачей.
- **Поиск и /research:** Yandex Search API + Crawl4AI + суммаризация локальной моделью; PubMed остаётся (без ПДн).
- **Маршрутизация Haiku/Sonnet:** остаётся детерминированной, лёгкий путь = та же модель с малым `max_tokens`.
- **Безопасность:** тот же сценарный гейт (7 углов фармы, суицид-метод, DAN, РПП, аллергены); при пробое — Qwen3Guard-Gen на выходе (модель по контексту, не кейворды).
- **Диагностика:** в `/diag` пинги `/v1/models`, ASR, Docling; метрика попаданий кэша префикса.

## План действий

1. **Юридика провайдера (владелец):** запросить у Cloud.ru и Yandex Cloud договор-поручение на обработку ПДн с явным допуском спецкатегории «здоровье». Это развилка: если оба откажут — сразу Путь 2.
2. **Eval (я):** экспорт системника и 20 схем, 90 сценариев по 10 категориям, прогон ×3 через Claude как baseline. Это нужно при любом пути и полезно уже сейчас как регрессионный гейт для текущего бота.
3. **Прогон кандидатов через eval:** по API — DeepSeek-V4-Flash, gpt-oss-120b (Cloud.ru), Qwen3.6-35B (Yandex); локально на арендованной на сутки карте — Qwen3.8-27B int4 и Gemma 4 31B. Выбор по порогам: валидные аргументы ≥ 97 %, must-refuse 100 %, судья ≥ 0.9 × Claude, p50 ≤ 10 с.
4. **РФ-VPS:** n8n + Postgres + GigaAM + Docling + Gotenberg, перенос workflow копией, переделки из списка выше.
5. **Теневой режим 1–2 недели** на тест-боте, сравнение ответов судьёй; затем фокус-группа; политики и оферта — параллельно (см. `ЮРИДИКА-РФ-план.md`).
6. **Переключатель на Путь 2** держать готовым: тот же vLLM-конфиг (`РФ-СТЕК-04`, чек-лист п. 3) поднимается на HOSTKEY 5090 за день.

## Что не удалось подтвердить

Позиции Qwen3.6/3.8 и Gemma 4 на MERA; русскоязычные тесты tool calling для них; реальные TTFT на 25k токенов (расчёт по FLOPs, откалиброван по чужим замерам); цены RTX 4090 у Timeweb/Yandex/MWS; актуальность бесплатного тира Cloud.ru; допуск спецкатегории ПДн в офертах провайдеров; доступность DuckDuckGo/Bing с российских IP. Всё это проверяется на шагах 1–3.

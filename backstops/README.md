# Детерминированные предохранители

Четыре чистые функции, которые в РФ-версии станут Code-узлами n8n. Они не зависят ни от
модели, ни от площадки, поэтому написаны и проверены здесь, до появления сервера.

Зачем это отдельно от промпта. По расчётам исследования открытая модель проседает
на 15–20 % в предметной точности и на 86–88 % в следовании длинному промпту против
95 % у Claude (`research/РФ-СТЕК-04`). Значит то, что сегодня подстраховка, становится
обязательным: правило в промпте модель может забыть, код — не может.

| Файл | Что делает | Куда встанет в n8n |
|---|---|---|
| `validate_args.js` | проверяет аргументы инструмента по JSON-схеме и возвращает модели русский текст ошибки | первым узлом каждого подчинённого workflow |
| `reply_format.js` | снимает разметку, ловит иероглифы, вырезает утёкший в текст вызов, собирает кнопки, режет на куски | узел «Ответ: нарезка» |
| `allergens.js` | сводит аллергены клиента и ингредиенты к категориям и матчит их (марципан → орехи) | подчинённый workflow `check_recipe_allergens` |
| `calendar.js` | считает дату, день недели, календарь недели, день программы и штамп в поясе клиента | узел `Build Profile Context` |
| `metric_contour.js` | разводит показатели по контурам: белый список — открытый, всё остальное — контур здоровья | подчинённый workflow `log_measurement` |
| `summary_filter.js` | ловит диагнозы, препараты и анализы в ночной выжимке о клиенте | `MemoryExtract`, перед записью в `client_summary` |
| `field_crypto.js` | шифрует значения контура здоровья ключом вне базы (AES-256-GCM с привязкой к строке) | все узлы, пишущие в схему `sens` |
| `meds.js` | общий словарь «похоже на лекарство» — один список на два предохранителя | используется двумя следующими |
| `done_when.js` | белый список условий автозакрытия; напоминание о препарате не закрывается НИКОГДА | первым узлом подчинённого workflow напоминаний |
| `program_days.js` | проверяет состав программы тренировок: дни подряд с 1, названия, непустые упражнения | подчинённый workflow `training_program`, до записи версии |

## Ограничения, из которых всё вытекает

1. **В Code-узлах n8n запрещён `require`** (`knowledge/memory/n8n-dataflow-gotchas.md`).
   Поэтому ни одной зависимости: валидатор JSON-схемы написан руками под то подмножество,
   которое используют схемы двадцати инструментов.
2. Экспорт устроен так, чтобы файл и запускался тестами, и копировался в узел как есть:
   `if (typeof module !== 'undefined') module.exports = …` в конце.
3. Данные справочников (категории аллергенов и карта составных продуктов) остаются в
   Postgres — здесь только логика. Тесты берут настоящие сиды из
   `knowledge/schema/allergen-layer2.sql`, поэтому расхождение с боевым справочником
   тест увидит.

## Проверка

    node --test 'backstops/tests/*.test.js'

101 тест. Отдельно проверяются ветки ошибок: число строкой, дата словом, значение вне
перечисления, лишние параметры, превышение лимита элементов, иероглифы, метка кнопок
не по правилам, вызов инструмента в тексте, полночь по часовому поясу клиента,
переход через месяц и год, чужой ключ, подмена шифротекста и перестановка значения
в другую строку, расхождение белого списка показателей между кодом и базой, автозакрытие
напоминания о препарате, дыра в нумерации дней программы.

Найденное этими тестами (уже исправлено) — одна и та же ловушка дважды: в JavaScript `\w`
не покрывает кириллицу, поэтому `\b` вокруг русских слов не срабатывает, а `\w*` не добирает
окончания. Из-за неё разбор кнопок ловил `knopki` и не ловил `кнопки`, а проверка выжимки
пропускала «аллергия» и «давление 128».
